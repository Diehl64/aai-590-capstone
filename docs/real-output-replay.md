# Saved-output simulated replay

This runner reuses independently evaluated radar, thermal, acoustic, and optional RF outputs. The source datasets are not synchronized. Selected rows are paired only for simulated software scenarios; they do not measure sensor-fusion accuracy. Every record has `simulated: true` and `review_required: true`, with a human-review reason. The runner does not make an autonomous alert decision or execute the proposed coordination agent.

## Available inputs

| Sensor | Committed handoff | Rows | Interpretation |
| --- | --- | ---: | --- |
| Radar | `data/model-outputs/radar-cnn-test-outputs.csv` | 11,050 | Saved RadarCNN test predictions. |
| Thermal | `data/model-outputs/thermal-dataset2-batch32-test-outputs.csv` | 2,631 | Dataset 2 frame decisions at the validation-selected operating point. |
| Acoustic | `data/model-outputs/acoustic-cnn-tuned-test-outputs.csv` | 57,015 | CNN-Tuned; the evidence document records the clean-validation 1% false-alarm threshold as 0.344. |
| RF | `data/model-outputs/rf-cnn-test-outputs.csv` | 2,400 | CNN v5, weight 1.50, seed 42, selected checkpoint; Machine threshold 0.45 on temperature-scaled validation probabilities. |

The runner preserves each CSV's saved labels and `score` values. It does not select a threshold, calibrate scores, or combine them. RF retains its literal six-class labels, including `Machine`: that label is not a confirmed drone. RF `calibrated_score` remains in the source CSV; this replay carries the unmodified `score` field. Thermal scores are detector confidence, including zero for some `no_drone` decisions, rather than a probability of the no-drone class. Agent score-domain and label-policy decisions require separate team review.

See [acoustic evidence](acoustic-model-evidence.md), [RF evidence and limitations](rf-v4-v5-evidence.md), and [the handoff contract](model-output-handoff.md). DADS lacks source/site identifiers, so acoustic results do not establish unseen-site generalization. RF exact duplicates and earlier test exploration limit interpretation of its saved test results.

## Run

From the repository root, with the repository's Python environment:

```powershell
# Radar + thermal: 10 scenarios; RF and acoustic remain missing.
python src/run_real_output_replay.py --no-acoustic --output results/real-output-replay/two-sensor-local.json

# Radar + thermal + acoustic: 16 scenarios; RF remains missing.
python src/run_real_output_replay.py --output results/real-output-replay/three-sensor-local.json

# Explicit RF addition: 25 scenario records from all four saved handoffs.
python src/run_real_output_replay.py --rf data/model-outputs/rf-cnn-test-outputs.csv
python src/plot_replay_scenarios.py
```

The checked-in `real-output-replay.json` and scenario-status PNG are generated by the last two commands. The default JSON destination remains `results/real-output-replay/real-output-replay.json`; use `--output` for other modes to retain the reviewed four-sensor artifact. The temporary two-/three-sensor files above are local verification outputs and should not be committed as duplicate artifacts. RF-specific scenarios require acoustic input; use `--no-acoustic` without `--rf` for the two-sensor mode.

`--acoustic PATH` accepts an explicitly named compatible CSV, including the supplied `acoustic-test-outputs.csv` or `acoustic-test-outputs-0.6.csv`. The chosen path is recorded in `input_files`. The runner never chooses between them based on test performance. A run with the 0.6 file is an explicitly requested operating-point check, not evidence that 0.6 was validation-selected. Keep alternate CSVs outside Git and have the team confirm the operating point before reporting it.

The runner checks the handoff schema, test-only split, sensor type, and dataset identity using `data/dataset-manifest.csv` and `data/dataset-id-aliases.csv`. Test fixtures pass their own registry/alias files through `--dataset-manifest` and `--dataset-aliases`; they do not depend on repository data.

With RF enabled, `--rf-manifest` defaults to the committed `data/rf-split-manifest.csv`. All RF source IDs must match its test partition exactly once. The manifest must exist: there is no fallback to remembered output IDs. Selected RF examples match their manifest class, except the deliberate Benign-to-Machine error case. The runner retains PR #55's list of 41 test files with exact copies outside test, checked against the committed integrity record, and excludes them from example selection. This is a selection safeguard, not a claim of a leakage-free RF evaluation. Acoustic examples require another window from the same recording starting 16,000 samples later; the runner fails if it cannot establish this full-length-window condition.

## Scenario coverage

The first ten cases cover radar/thermal agreement, conflict, non-drone predictions, missing evidence, delay, and low-quality thermal evidence. Acoustic adds six cases for acoustic-only evidence, disagreement, missing evidence, delay, and low quality. When RF is omitted, every RF evidence record remains missing with no prediction or score.

The explicit RF run extends the existing PR #55 catalog with cases 017–025:

| Case | Scenario |
| --- | --- |
| 017 | RF `Machine` alongside three drone predictions; no conversion of `Machine` into a drone label. |
| 018 | A saved RF Benign-to-Machine error alongside other non-drone predictions. |
| 019 | RF `Benign` alongside three drone predictions. |
| 020 | RF is the only available evidence. |
| 021 | RF `Broadband_Jam` alongside three drone predictions. |
| 022–024 | RF delayed, low quality, or missing. |
| 025 | Radar low quality while the other evidence is present. |

Cases 001 and 017 intentionally retain the same selected evidence and statuses from the proposed catalog. Thus 25 records do not mean 25 distinct evidence combinations or independent trials. Their count is not a performance metric. Synthetic event timestamps and injected missing/delayed/quality states are scenario controls, not measured synchronization, latency, or input degradation.

The JSON preserves output IDs and source times in each evidence reference and records the input paths. All scenarios require human review. The figure shows evidence availability states only. Neither artifact establishes combined accuracy, calibrated combined confidence, operational false-alert performance, or real-world sensor association.
